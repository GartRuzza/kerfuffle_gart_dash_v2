## At a glance

**The table now shows the real league, ranked AND priced the KERFUFFLE way.** The pipeline is complete through the valuation engine: `npm run archive` saves verbatim snapshots (#10), `npm run ingest` normalizes them + the FantasyPros projections (#12/#18), `npm run ingest:historical` loads the 2024/25 stat history + 2025 salaries (#17), and **`npm run engine` (#18 + #20) turns FantasyPros' projected stat lines — plus an *estimated* first-down component from our own league history — into KERFUFFLE projected points, then Kerf ranks/tiers, and then auction dollars: a league-generic Kerf Value, a Raccoons-specific Roster Value, two market prices, and Edge.** The app renders all of it: real rosters, salaries, contracts, statuses, free agents, FantasyPros rankings/tiers, **Kerf ranks/tiers with quarterbacks correctly at the top** (Josh Allen #1 overall), and now **the three money numbers the product exists to show** — what a player is worth to us, what the market pays, and the gap. What does **not** exist yet: **defenses' Kerf/dollar numbers** (the offensive feed can't score defense — DST stays "—"), **persisted/owner-saved ceilings** (still session-only — that's the auction-prep lens), and the three lenses as dedicated flows.

- **Built** — works end to end, in the product, usable by a real user today.
- **Partial** — some of it exists, but a real user cannot rely on it yet. The gap must be named in the section below.
- **Not built** — no usable implementation exists, even if code has been started.

## Partially built — what exactly is missing

**The dollar columns are now filled for offense (issue #20).** What still renders as "—", and why:

- **Defenses (DST) show "—" for every Kerf and dollar column** — DST is excluded from the projection engine (its scoring can't be derived from the offensive projection feed — owner, 2026-08-26), so it has no points, no PAR, and no price. Defenses keep their market positional rank/tier from the 1-QB board only.
- **Ceiling** seeds from **Kerf Value** (now a real number) and is owner-editable, but **still resets on reload** (session-only). Persisting ceilings "for auction day" is the auction-prep lens (roadmap #10), not this issue.
- **Roster Value / Market prices are blank for anyone the engine can't price** (defenses, and any offensive player FantasyPros doesn't project).
- **Kerf ranks/tiers, Proj Points, and now Kerf Value / Roster Value / Market / Edge are filled** for projected offense (incl. free agents) — they are no longer part of this gap.

The prototype-era description below is kept for history of what the UI shell does:

**Player table prototype — what it does (v2 redesign, Phases 1–2):** runs locally (`npm install`, then `npm run dev`, at http://localhost:3000) as one screen with a **dark theme**; ~80 real-name players across QB/RB/WR/TE spanning a free-agent pool, the Rangoon Raccoons' roster, and 3 rival rosters; columns Owner, Player, **Pos (colored badge)**, Team, Kerf Ovr Rank, Kerf Pos Rank, Proj Points, Kerf Value, Ceiling, Edge (green +/red −), Market Value, Ovr ECR, Pos ECR, Dyn Ovr ECR, Dyn Pos ECR, Salary, Contract, tinted into **GartStats / Market / Contract Info** groups with a color-key legend; sorting with a filled caret; **FantasyPros-style tier bands** driven by six mock tier dimensions (bands appear only under a matching rank sort; the coupled sort↔position rules live in `lib/tierRules.ts`).

## Current limitations

- **Projection + valuation engines built.** Kerf ranks/tiers, Proj Points (#18) and now Kerf Value / Roster Value / Market / Edge (#20) are all live. The engine is a **manual step** — `npm run engine` after ingest — so every Kerf number (points and dollars) is as fresh as the last engine run; re-run it after refreshing data.
- **The valuation is a single-season VORP with a superflex-aware QB floor ([D-19](../decision_log.md)).** The QB replacement level sits at the **last rostered QB ≈ QB30** (not the last starter QB24), because superflex forces two QB slots + backups and projected QB scoring cliffs after ~QB30 — so elite QBs carry real value-over-replacement. Live: **Josh Allen $151 (co-top with Gibbs $152); 6 QBs clear $100.** RBs remain strong but no longer dominate (Gibbs eased $201→$152). Prices still sum to the cap; QB1 is still overall #1. The QB depth is a tunable constant (`QB_REPLACEMENT_PER_TEAM`, 2.5) — 2.0 reverts to textbook last-starter, higher prices QBs more aggressively. Dynasty/contract length stay separate context, never blended (D-13).
- **DST is not priced.** Defenses have no projection (#18), so no PAR and no dollars — every Kerf/dollar column shows "—" for them. The DST12 baseline is documented for completeness only.
- **Market (Now) shows the real salary for rostered players; only free agents use the curve** ([D-18](../decision_log.md)). So a rostered player's Market (Now) always matches his visible salary, and Edge reads as a truthful overpay/underpay-on-contract signal (Lamar $201 salary → Edge −$115). Market (Auction), and Market (Now) for free agents, still come from the price curve.
- **The price curve is thin at the extremes.** The in-season curve is fit from only ~12 rostered players per position (fewer at TE/QB); the pre-auction curve from the 2025 salaries. A curve price is "what the Nth-best player at this position costs" read by Kerf positional rank — a transparent step curve, but a deep player flattens to the cheapest observed salary. The curve basis is inspectable (`price_curve` table).
- **The $1-minimum roster size (19 spots/team, bench in, IR out) is a tunable assumption**, and only shifts the dollar scale ~2% either way (`ROSTER_SPOTS_PER_TEAM` in `tools/engine/valuation.mjs`). Prices sum to the cap by construction.
- **Team defenses have no overall rank.** FantasyPros' superflex boards are offensive players only; DSTs carry positional rank + tier from the 1-QB board and sort last on overall-rank sorts (owner's call, D-12). Rostered-player ranking coverage is 162/170 either way.
- **Data freshness is manual.** The routine is `npm run archive` → `npm run ingest` → refresh; nothing is scheduled (deliberate — an expired-cookie scheduled run would silently collect nothing). The banner date is the tell.
- **Free agents come from the FantasyPros board, not CBS's FA page** (`/players` is JS-rendered; not yet captured). A player nobody rosters *and* FantasyPros doesn't rank isn't in the table; FA Proj Points are blank.
- **Some players have blank salaries on CBS itself** (pending assignment): stored as unknown, counted $0 toward the cap, warned on every ingest.
- **Post-auction, CBS shows just-won players with contract length "0"** (salary set, term not yet chosen). Ingest stores "0" as an **unknown term** (`contract_years = null` → Contract shows "—") plus a per-player warning, rather than rejecting the snapshot. A contract value **outside {0,1,2,3,4}**, or a genuinely **blank** contract cell, still rolls the whole run back loudly. The **live post-auction snapshot (2026-08-27) ingested cleanly: 241 rostered players, 40 with an unknown "0" term** awaiting assignment in CBS. (Behavior change 2026-08-27; no schema change — the `contract` CHECK already permits null.)
- **Transactions are in the database, not the UI** — all 60 real log entries (with inferred types; CBS has no type column) are queryable and lineage-tracked, but no screen shows them yet. FAB bid amounts remain unsolved upstream (recoverable via resulting salaries).
- **Dead-cap handling is built but untested against a live example** — zero exist pre-auction. Detection + storage per D-11 are unit-tested on synthetic fixtures; the first real cut should be spot-checked.
- **Limited persistence.** Custom *views* persist in browser localStorage (per browser, not synced); edited ceilings still reset on reload. The SQLite store persists league data; no accounts.
- **Local only.** The app is not deployed anywhere; it runs on the owner's machine via `npm run dev`.
- **Both data sources are now access-proven (read-only).** CBS via the session-cookie + HTML-parse method (spike #5); **FantasyPros via its official JSON API** (spike #7), and the CBS↔FantasyPros join is a direct `cbs_player_id` match. The **HOF cap-lift is now formally confirmed (issue #11):** ranking endpoints return the **full board** (draft PPR 521, HALF 883, etc., not the 10-of-520 preview), `tier` is **`premium`**, and the previously-`403` **projections / player-metadata / news** endpoints return data. ⚠ **Caveat:** `public_api_limited` still reports **`true`** even on HOF, so it must **not** be used as the tier signal (use row count + `tier`). **ADP is still `403`** — likely a wrong path/params, not a gate; nice-to-have, not blocking. See [`../fantasypros_data_discovery.md`](../fantasypros_data_discovery.md) §8.
- **Not every CBS page is in the static HTML (issue #11; transactions solved in #12).** Rosters, `/rules`, `/standings`, `/history` parse cleanly to static tables; `/transactions` turned out to paginate via **plain URL parameters** and is now fully captured and ingested. Still JS-rendered/unsolved: `/players` (the FA pool — why FAs derive from FantasyPros for now), `/draft/results` (auction values), `/scoring/live`. Also: the roster `Pos` column is the lineup **slot** (incl. FLEX/RB-WR-TE), not the player's position — ingestion reads the true position from the Players cell. - **The raw archive is manual and current-season only.** `npm run archive` runs when the owner chooses (tied to the ~weekly CBS cookie refresh); nothing is scheduled — a scheduled task with an expired cookie would silently collect nothing, so automation is deliberately deferred (roadmap "Later"). **Historical CBS seasons are not captured** — the year switch isn't a URL parameter (still unsolved); the archive holds the current season only. One CBS page, `players-rankings`, returns a `302` redirect rather than content — archived verbatim as-is; a future parser should expect it.
- **Contract-length location resolved (spike #5): CBS exposes per-player contract length** (a "Contract" column, 1–4 yrs, on roster pages) — this closes roadmap open decision #1.
