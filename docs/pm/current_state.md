## Partially built — what exactly is missing

**The table's engine columns are deliberately empty — that is the named gap, not a Partial status.** "Player table (on real data)" is Built as scoped by issue #12: every *sourced* value is real (rosters, salaries, contracts, statuses, transactions-in-DB, rankings, tiers, CBS's own projections for rostered players). What renders as "—" and why:

- **Kerf Ovr/Pos Rank, Kerf tiers, Kerf Value, Market Value, Edge** — outputs of the valuation engine (roadmap #7), which does not exist. Nothing is invented to fill them.
- **Ceiling** starts blank — it pre-fills from Kerf Value by design, which is null until the engine lands. Still editable, still session-only.
- **Proj Points for free agents** — CBS's projections for unrostered players live on the JS-rendered `/players` page, which isn't captured yet; rostered players show CBS's real KERFUFFLE-scored projection.

The prototype-era description below is kept for history of what the UI shell does:

**Player table prototype — what it does (v2 redesign, Phases 1–2):** runs locally (`npm install`, then `npm run dev`, at http://localhost:3000) as one screen with a **dark theme**; ~80 real-name players across QB/RB/WR/TE spanning a free-agent pool, the Rangoon Raccoons' roster, and 3 rival rosters; columns Owner, Player, **Pos (colored badge)**, Team, Kerf Ovr Rank, Kerf Pos Rank, Proj Points, Kerf Value, Ceiling, Edge (green +/red −), Market Value, Ovr ECR, Pos ECR, Dyn Ovr ECR, Dyn Pos ECR, Salary, Contract, tinted into **GartStats / Market / Contract Info** groups with a color-key legend; sorting with a filled caret; **FantasyPros-style tier bands** driven by six mock tier dimensions (bands appear only under a matching rank sort; the coupled sort↔position rules live in `lib/tierRules.ts`).

**Phase 2 (view system) adds:** a 3-way **roster toggle** (All / Rostered / Free Agents) beside a **Manager dropdown** (All / each team); the **position dropdown** (All/SuperFlex/Flex/QB/RB/WR/TE); a **column picker** to show/hide columns; **drag-to-reorder** column headers (@dnd-kit, mounted client-side to stay SSR-safe); and **saved views** — five built-in default views (Full, Auction Prep, Waivers, Trades, Start/Sit) plus user-created custom views, **persisted in browser localStorage**. Opens to Full. The table scrolls inside a bounded, sticky-header container so both scrollbars stay on screen. (Ovr ECR / Dyn Ovr ECR display the unique overall rank so tier bands stay contiguous.)

**Phase 3 adds:** a **Data Dictionary** overlay (button at the bottom) that defines each column — a one-line definition plus an expandable bulleted deep-dive (mechanics + source). **The structure is built but most content is placeholder** (flagged "Placeholder"), to be filled after data discovery (roadmap #2–3) and the engine (#4–6).

**What it deliberately does *not* do:** no real data (all values, ranks, and the six mock tier dimensions are hand-authored or derived, not computed by an engine); the data-dictionary content is mostly placeholder; ceilings still reset on reload (only view configs persist); no accounts, no deployment, no real data schema. DST has a badge color but no DST players exist in the mock data.

## Current limitations

- **No engine yet.** Kerf values/ranks/tiers, Market Value, Edge, and ceiling suggestions are "—" until the valuation engine (roadmap #7) exists. The default sort and tier bands are the **FantasyPros draft board (standard scoring, owner's choice)** in the meantime.
- **Data freshness is manual.** The routine is `npm run archive` → `npm run ingest` → refresh; nothing is scheduled (deliberate — an expired-cookie scheduled run would silently collect nothing). The banner date is the tell.
- **Free agents come from the FantasyPros board, not CBS's FA page** (`/players` is JS-rendered; not yet captured). A player nobody rosters *and* FantasyPros doesn't rank isn't in the table; FA Proj Points are blank.
- **Three t7 players have blank salaries on CBS itself** (pre-auction oddity, likely pending assignment): stored as unknown, counted $0 toward the cap, warned on every ingest.
- **Transactions are in the database, not the UI** — all 60 real log entries (with inferred types; CBS has no type column) are queryable and lineage-tracked, but no screen shows them yet. FAB bid amounts remain unsolved upstream (recoverable via resulting salaries).
- **Dead-cap handling is built but untested against a live example** — zero exist pre-auction. Detection + storage per D-11 are unit-tested on synthetic fixtures; the first real cut should be spot-checked.
- **Limited persistence.** Custom *views* persist in browser localStorage (per browser, not synced); edited ceilings still reset on reload. The SQLite store persists league data; no accounts.
- **Local only.** The app is not deployed anywhere; it runs on the owner's machine via `npm run dev`.
- **Both data sources are now access-proven (read-only).** CBS via the session-cookie + HTML-parse method (spike #5); **FantasyPros via its official JSON API** (spike #7), and the CBS↔FantasyPros join is a direct `cbs_player_id` match. The **HOF cap-lift is now formally confirmed (issue #11):** ranking endpoints return the **full board** (draft PPR 521, HALF 883, etc., not the 10-of-520 preview), `tier` is **`premium`**, and the previously-`403` **projections / player-metadata / news** endpoints return data. ⚠ **Caveat:** `public_api_limited` still reports **`true`** even on HOF, so it must **not** be used as the tier signal (use row count + `tier`). **ADP is still `403`** — likely a wrong path/params, not a gate; nice-to-have, not blocking. See [`../fantasypros_data_discovery.md`](../fantasypros_data_discovery.md) §8.
- **Not every CBS page is in the static HTML (issue #11; transactions solved in #12).** Rosters, `/rules`, `/standings`, `/history` parse cleanly to static tables; `/transactions` turned out to paginate via **plain URL parameters** and is now fully captured and ingested. Still JS-rendered/unsolved: `/players` (the FA pool — why FAs derive from FantasyPros for now), `/draft/results` (auction values), `/scoring/live`. Also: the roster `Pos` column is the lineup **slot** (incl. FLEX/RB-WR-TE), not the player's position — ingestion reads the true position from the Players cell. See [`../cbs_data_discovery.md`](../cbs_data_discovery.md) §8.
- **KERFUFFLE scoring is now extracted (issue #11)** into committed structured form ([`../profiles/cbs_scoring_rules.json`](../profiles/cbs_scoring_rules.json)) — parsed from `/rules`, never hardcoded. ⚠ **CBS diverges from the written constitution** (defensive Int = 2 on CBS vs 3 in the constitution); **CBS is authoritative** for the engine. Dead-cap pseudo-rows: **0 in the profiled pre-auction snapshot** (detection rule confirmed: a roster row with a salary but no player id); **10 Practice-Squad players** across the league (ordinary player rows in a `Practice` section). This evidence resolved roadmap open decision #7 (owner, 2026-08-25 — see decision **D-11**), and the schema now implements it.
- **The raw archive is manual and current-season only.** `npm run archive` runs when the owner chooses (tied to the ~weekly CBS cookie refresh); nothing is scheduled — a scheduled task with an expired cookie would silently collect nothing, so automation is deliberately deferred (roadmap "Later"). **Historical CBS seasons are not captured** — the year switch isn't a URL parameter (still unsolved); the archive holds the current season only. One CBS page, `players-rankings`, returns a `302` redirect rather than content — archived verbatim as-is; a future parser should expect it.
- **Contract-length location resolved (spike #5): CBS exposes per-player contract length** (a "Contract" column, 1–4 yrs, on roster pages) — this closes roadmap open decision #1. Two things remain unsolved in CBS: programmatic **historical-season** retrieval (the year filter is JS/POST-driven) and **FAB winning-bid amounts** in the transaction log. See [`../cbs_data_discovery.md`](../cbs_data_discovery.md).
- Next.js 15 pulls in 3 high-severity npm advisories through build-time transitive deps (postcss; sharp, which we don't use). The only patch upgrades Next to v16, a breaking major-dependency change — deferred as a follow-up decision (see reality log). Negligible risk for a local, no-image prototype.

## Latest implementation summary

IR**, contract years 1–4), idempotent upserts on natural keys, full `pull_id`/`fetched_at` lineage; a failure rolls the run back untouched. **Archiver extension (owner-approved):** the paginated transaction log is now fully captured (print-all + every page; 60 transactions vs 27 before) and a dynasty-STD probe added. **UI:** `lib/mockData.ts` deleted; the single data-access module (`lib/data/`) reads the board view; free agents derive from the FantasyPros draft-STD board (owner's display choice); engine columns render "—"; ceiling starts blank (seeds from Kerf Value when the engine exists); MOCK banner → "League data as of \<date\>"; DST is a real position; tier bands are FantasyPros' real tiers; default sort = Ovr ECR. **Validated:** 69 unit tests (incl. bad-fixture loud rejection + DB-level idempotency), clean build, live ingest of all 3 archive runs, real-data render check. Notable data realities: FP's dynasty board is scoring-agnostic and pre-season "ROS" returns the draft board (ingest trusts payload self-description and dedupes → 9 boards/pull); three t7 players have blank salaries on CBS itself.

**2026-08-25 — Source-profiling spike (issue #11, roadmap #5).** Built a discovery tool at [`tools/profile/`](../../tools/profile/) (`npm run profile`) that walks the latest raw archive (issue #10) and emits a **committed, shape-only** field profile to [`docs/profiles/`](../profiles/): `cbs_field_profile.json`, `fantasypros_field_profile.json`, the `/rules` scoring config **in full** (`cbs_scoring_rules.json`, 24 rules), and a readable `PROFILE.md` answering the spike's six questions. **Owner decision (question raised mid-build):** because the repo is **public**, player/roster/market values are masked to shape (`Ja'Marr Chase`→`Aa'Aaaa Aaaaa`); only non-private structural enums (positions, statuses, contract-year domain, bye weeks) list real values; league *rules* are committed in full. **2026-08-25 — Raw snapshot archival tool (issue #10, roadmap #4).** Promoted the throwaway spike pulls into a durable, repeatable operator tool at [`tools/archive/`](../../tools/archive/) — `capture.mjs` (the archiver), `check-cookie.mjs` (promoted cookie checker), `shared.mjs`, and a how-to-run `README.md`, wired to `npm run archive` and `npm run archive:check-cookie`.
